# base contract

One claim per line, each naming the check that proves it. Tags follow the claims ledger: *Type* (the program does not compile), *Runtime* (a check returns an error), *Obligation* (the host's, proven against every `Store`), *Non-claim*.
Checks: `ui:x` is `tests/ui/fail/x.rs` with its committed `.stderr` (rustc code given) and the compiling twin `tests/ui/pass/x.rs` one line and one token away (`just twins`; `just ledger` runs with every feature on, B13); `api` is the committed `public-api.txt` from rustdoc JSON on a pinned nightly (`just api`), one line per item, item attribute (`attr`), public field (tuple and variant fields included) and method with its full signature; `unit:m::t` is a test in `src/m.rs`; `it:f::t` is `tests/f.rs`; `mutants:m` is `just mutants` over `src/m.rs` (B14), named only where the claim's functions have a viable mutant (constructors and accessors whose every replacement fails to compile are measured by their unit tests); `conf:c` is case `c` of `testkit::store_conformance`, run here against `testkit::MemStore`; `race:t` is `tests/race.rs`; `wipe:t` is a test of the `wipe` member, which reads freed memory and so is outside the workspace lints.

## Type
- T1 `Secret<N>` has no `Display`: ui:secret_display (E0277), api.
- T2 `SecretBytes` has no `Display`: ui:secret_bytes_display (E0277), api.
- T3 `Secret<N>` has no `Clone`: ui:secret_clone (E0277), api.
- T4 `SecretBytes` has no `Clone`: ui:secret_bytes_clone (E0277), api.
- T5 `Secret<N>` cannot be compared with `==`: ui:secret_eq (E0277), api.
- T6 `SecretBytes` cannot be compared with `==`: ui:secret_bytes_eq (E0277), api.
- T7 `Secret<N>` has no `Serialize`, so no serde record field holds one: ui:secret_serialize (E0277; the twin is `Digest`, which serializes only under `serde`), api.
- T8 `SecretBytes` has no `Serialize`: ui:secret_bytes_serialize (E0277), api.
- T9 A secret cannot be a `StoreKey` (no `Clone`, no `Ord`); store-facing keys take `Digest`: ui:secret_key (E0277, E0369).
- T10 A verdict leaves `Pending` only through `settle`: api (no accessor, no public field, no `map`; the `lift` and `join` signatures keep it inside), ui:pending_field (E0616), `Debug` prints only the effect id (it:golden::debug_redacts), and ui:pending_verdict shows a closure cannot move it out through `map` (E0599).
- T11 `Receipt` has no public constructor or field; `Effect::host_applied` is the one mint: ui:receipt_fields (E0451), api (no public field; `effect_id` only reads); ui:receipt_forge (E0599) is the named-guess illustration.
- T12 `Receipt` is not `Clone`: ui:receipt_clone (E0277), api.
- T13 No put without a guard on its key (`create` is `Absent` plus put, `update` is `Unchanged` plus put): api (the only writes are the builder's six guarded ones and the four one-op constructors of R33); ui:unguarded_put (E0599) is the named-guess illustration.
- T14 No delete without a guard on its key (`consume`, or `delete` against a seen row): api; ui:unguarded_delete (E0599) is the named-guess illustration.
- T15 `EffectId` has no public constructor or field, so an id comes only from `Entropy` or a merge: ui:effect_id_fields (E0423), api.
- T16 `SecretBytes` and `Secret<N>` hold their bytes in private fields, so only `expose` reads them: ui:secret_bytes_fields (E0423), api (no public field).
- T17 `Pending` and `Builder` are `#[must_use]`, so an unsettled verdict dropped as a statement is the `unused_must_use` lint: ui:pending_unused (the lint at deny; the twin warns), api (`attr Pending must_use`, `attr Builder must_use`).
- T18 Every public enum is `#[non_exhaustive]`, so a consumer's match keeps a wildcard arm: ui:error_kind_exhaustive (E0004), api (one `attr ... non_exhaustive` per enum).

## Runtime
- R1 `b64url_encode` and `b64url_decode` (a wrapper over `base64ct`'s unpadded base64url) agree with RFC 4648 section 10 under the section 5 alphabet: it:vectors::rfc4648_section10 (total 28, 7 checked), mutants:b64url.
- R2 Symbols 62 and 63 are `-` and `_`: unit:b64url::alphabet_edges.
- R3 Padding is `Malformed`: unit:b64url::padding_is_malformed.
- R4 A symbol outside the alphabet (`+`, `/`, space, non-ASCII) is `Malformed`: unit:b64url::foreign_symbol_is_malformed.
- R5 A length of 1 mod 4 is `Malformed`: unit:b64url::lone_symbol_is_malformed.
- R6 A non-canonical tail (nonzero trailing bits) is `Malformed`, so decoding is injective: of all 64 final symbols a 2-symbol tail accepts exactly `A Q g w` and a 3-symbol tail exactly the 16 with two zero low bits: unit:b64url::noncanonical_tail_is_malformed.
- R7 Whatever decodes re-encodes to the same text: it:corpus::b64url_decode_corpus (21 committed seeds of `fuzz/fuzz_targets/b64url_decode.rs`, non-canonical tails `Zo` and `ZmC` among them), `just fuzz` (10 minutes on nightly, against the fuzz crate's committed lock), run by the CI job `check-rust-scheduled` after `just mutants rows`; the project has no pipeline schedule yet, so that job has not run.
- R8 `Debug` of `Secret<N>` and `SecretBytes` prints no secret byte, of `RandCore` no generator state, and of `Pending` only its effect id: it:golden::debug_redacts against `tests/golden/debug.txt`, unit:entropy::rand_core_debug_prints_no_generator_state, unit:effect::pending_debug_shows_only_the_effect_id.
- R9 `generate` draws exactly `N` bytes from `Entropy`: unit:secret::generate_draws_n_bytes.
- R10 `ct_eq` is true only when every byte and the length match: unit:secret::ct_eq_compares_every_byte, mutants:secret; each `ct_eq` body is `subtle`'s `ConstantTimeEq` over both byte slices: `just confine`.
- R11 `digest` is SHA-256 of the secret bytes: unit:secret::digest_is_sha256.
- R12 A key named twice in one builder is `Overlap`: unit:effect::overlap_in_builder.
- R13 A merge of effects sharing a key is `Overlap`: unit:effect::overlap_in_merge.
- R14 A non-injective lift is `Overlap`: unit:effect::overlap_in_lift.
- R15 A lift that changes a key's `scope()` is `ScopeChanged`: unit:effect::scope_changed_in_lift, mutants:effect.
- R16 `build` of an effect with no guard is `Empty`: unit:effect::empty_build, mutants:effect.
- R17 An effect whose guards plus writes exceed `MAX_EFFECT_SIZE` (128, asserted as a literal) is `TooLarge` from `build` and `merge`, and exactly 128 builds: unit:effect::size_bound; the builder latches its first fault and stops growing, and `merge` tests the bound before moving anything, so an oversize effect is never an allocation: unit:effect::oversize_builder_stops_growing, mutants:effect.
- R18 `domain` is `SpansDomains` unless every key maps to one domain, the third of three keys included: unit:effect::domain_of_keys, mutants:effect.
- R19 `settle` with another effect's receipt is `WrongReceipt`; its own receipt yields the verdict; `Receipt::effect_id` names the effect it settles: unit:effect::settle_by_receipt, mutants:effect.
- R20 The id is 16 bytes of `Entropy`; `lift` keeps it; `merge` takes the first 16 bytes of SHA-256 of both ids in order: unit:effect::ids.
- R21 `check` names every failed guard (`Missing`, `Changed`, `Present`) and passes when all hold: unit:effect::check_names_each_failure, mutants:effect.
- R22 `guards`, `puts` and `deletes` show exactly what the builder paired, consumed rows among the deletes: unit:effect::views, mutants:effect.
- R23 No builder, merge or lift sequence yields a write without a guard on its key, a key twice, or more than 128 guards plus writes: it:effect_props::construction_never_unguarded (proptest, fixed seed, 512 cases, distinct keys by construction and one repeated at times).
- R24 Against the reference store, an effect applies whole or not at all, and a `Conflict` names exactly the guards that fail: it:effect_props::all_guards_or_nothing (proptest, fixed seed, 512 cases, guards drawn mostly holding so both halves are common).
- R25 `Rows::get` reports a loaded row, an absent row, a corrupt row, and `None` for a key never loaded: unit:store::rows_slots.
- R26 `UnixTime::saturating_add` and `saturating_sub` saturate at `u64::MAX` and the epoch; `checked_duration_since` is `None` when the other instant is later: unit:time::arithmetic_saturates.
- R27 `Secret::<N>::from_b64url` takes canonical unpadded base64url of exactly `N` bytes and is `Malformed` otherwise: unit:secret::from_b64url_takes_exactly_n, unit:b64url::exact_length.
- R28 `Digest` has a text form (43-symbol unpadded base64url) that round-trips, and under `serde` serializes as that text and deserializes only from it, with an error that does not echo the rejected text: unit:secret::digest_text_round_trips, unit:secret::digest_serde_is_text.
- R29 The vector runner counts only checked cases against its floor, and a zero floor, a total or SHA-256 that disagrees with `SOURCES.toml` or an unlisted file fails: testkit unit:vectors (seven cases).
- R30 The builder takes and returns itself by value (`#[must_use]`), so a decision is one expression; `update`, `delete` and `expect` take the seen row as any `Row<S>` and read only its version, so a consumer guards a typed row in an effect over its store record: unit:effect::seen_rows_of_any_type, api.
- R31 `b64url_decode` reads at most `MAX_B64URL_TEXT` (65,536 symbols, asserted as a literal); longer text is `TooLarge` (displayed as `input or effect exceeds its bound`), before anything is allocated and before any `Malformed`: unit:b64url::text_past_the_cap_is_too_large, unit:error::too_large_names_text_and_effects, mutants:b64url.
- R32 The storage a secret owns is wiped: a dropped `Secret<N>` leaves its slot zero, a dropped `SecretBytes` buffer is zero when freed, and a text `b64url_decode` refuses leaves its decode buffer zero when freed: wipe:owned_storage_is_wiped (a slot dropped in place, and a global allocator that reads each block as it is freed), mutants:secret.
- R33 `Effect::created`, `updated`, `consumed` and `deleted` return, without a `Result`, the one-op effect the builder's `create`, `update`, `consume` and `delete` build from the same entropy: unit:effect::single_ops_are_the_builder_ops.

## Obligation (every host's; `testkit::store_conformance` on the shell's exact apply path)
- O1 One transaction per apply: every guard holds or nothing is applied (puts, deletes and consumes alike), the `Conflict` names each failed guard, and every apply that commits answers its own effect's receipt: conf:atomic (every case checks each receipt it is given). Each case is proven sensitive by it:conformance::each_lie_is_caught_by_its_case, twenty-two stores with one lie each that must fail in the case named here, the same store without a lie passing (it:conformance::the_honest_liar_passes); atomic catches skipped writes, a conflict reported as `Error`, puts or deletes applied despite a conflict, and another effect's receipt.
- O2 A guard that fails after a write in key order leaves that write unapplied: conf:fails_after_write (a store that stops at the first failing guard).
- O3 An effect fails only on a key an earlier winner wrote, so disjoint effects and effects that only `expect` one row both apply; `Consume` checks existence only, so a decision that depends on a row's content uses `delete` against the seen row: conf:expect_shared (a store that bumps an expected row), conf:disjoint (a store that checks a table-wide version), race:pairs, race:consume_checks_existence_only, race:a_loser_fails_only_on_winners_writes.
- O4 Concurrent applies equal some serial order once each loser is re-decided against the winners' state: race:pairs, race:triples (each pins its seeded conflict total, and `race` asserts the op sequence it applied in each raced order is that order), testkit unit:race::every_order_once.
- O5 Re-applying an applied effect returns `Ok` with a receipt that settles it, and writes nothing twice: conf:reapply (a store with no applied-id record; it compares versions, which a second write of the same records changes); the second apply answers as the first: race:same_twice, race:same_twice_catches_a_store_that_forgets_applied_ids.
- O6 The applied-id record shares the effect's transaction and is checked before any guard, and a conflicted effect's id is not recorded: conf:reapply (a store that checks the id after the guards), conf:conflict_not_applied (a store that records a conflicted id).
- O7 A store's own constraint failure is `Conflict`, never `Error`: conf:duplicate_create (a store that leaves `Absent` on a create to a unique constraint that errors).
- O8 A row at or after its expiry is absent to `load` and to every guard (`expect`, `consume`, `update` and `delete` are `Missing`, `create` holds), purged or not, and an update's deadline holds: conf:expired (stores live at the deadline, whose guards ignore expiry, whose `consume` ignores it, whose writing guards ignore it, or whose update drops it).
- O9 A version never repeats for a key, across delete and recreate and across a create over an expired row, so a stale `expect` of the old incarnation is `Changed`: conf:recreate (a store with per-key version counters), conf:expired (a store whose create over an expired row keeps its version).
- O10 An effect at the bound applies: 128 guards, and 64 creates, updates, deletes or consumes: conf:at_bound (a store that refuses past 100 guards, a store that refuses past 40 deletes).
- O11 Every key a decision loaded is guarded in its effect: race:read_set (the reference store records loads; the case is a probe that must fail).
- O12 A `Receipt` is minted only after its effect committed: `host_applied` is in clippy `disallowed_methods` for every crate but `base`, at a level B4 proves: it:lint_canary; `just confine` fails on a `.rs` file that names `host_applied` outside `confine.toml`'s `mint` list (`src/effect.rs`, the two store modules and the canary).
- O13 `expose` is read only in modules a `CONTRACT.md` names; `base` names none: `just lint` (it:lint_canary), `just confine` (names `expose` outside `confine.toml`'s `read` list: `src/secret.rs` and the canary). `base`'s own `src/` does not resolve the `base::` path, so its unit tests call `expose` unflagged.
- O14 After `Conflict` a decider re-decides at most `REDECIDE` (3) times; after `Error` the host re-applies the same effect with the decision's `now`, within `Retry`: consumers' contracts; unit:store::redecide_is_three, race:a_loser_redecides_up_to_three_times, race:a_loser_gives_up_after_three; the reference store's injected lost result commits and its re-apply settles: testkit unit:store::a_lost_result_commits_and_a_reapply_settles.
- O15 A repeated effect id with other keys is never `Ok`, since it would settle a verdict with nothing written: conf:reused_id (a store that answers `Ok` for any applied id); the reference store records each applied id's keys and answers `Fault::ReusedId`. That the `Entropy` given to `Effect::builder` never repeats a 16-byte draw among effects one store sees is the host's obligation, unchecked; `testkit::seeded(n)` repeats for the same `n`, so a test draws every effect for one store from one advancing source.

## Build
- B1 `no_std` + `alloc` for wasm32-unknown-unknown and thumbv7em-none-eabi, with `std`, `rand_core` and `serde` features off and on: `just wasm`, `just thumb`.
- B2 `RandCore` makes any `rand_core::CryptoRng` an `Entropy`: testkit `seeded` is built on it, it:vectors and every seeded test.
- B3 MSRV 1.89, workspace-wide, against the committed lock: `just msrv` (`--locked`), and `just lock` fails first when a manifest changed without its lock.
- B4 Each `clippy.toml` path is an error at the workspace lint level, without `-D warnings`: `confine.sh --canary` (in `just lint`) removes every canary `expect` from it:lint_canary in a copy inside the tree, so the real cargo configs and environment apply, and requires the set of paths clippy names to equal the set `clippy.toml` lists.
- B5 Each other deny-list lint is an error at the workspace level: `confine.sh --canary` appends to `src/lib.rs` one probe per lint (unwrap, expect, panic, index, `as`, print, dbg, unsafe, an undocumented and an unreachable `pub` item, and a renamed lint name) and requires each an error.
- B6 `unsafe_code`, `missing_docs`, `unreachable_pub`, `renamed_and_removed_lints`, `indexing_slicing`, `as_conversions`, `print_stdout` and `dbg_macro` are `forbid`, so rustc rejects any allow of them, a macro-generated one included (E0453); forbidding `renamed_and_removed_lints` closes the alias class, where a renamed name such as `clippy::option_unwrap_used` or `clippy::result_expect_used` would otherwise allow an unwrap or expect unseen; `unwrap_used`, `expect_used`, `panic`, `disallowed_methods` and `disallowed_types` are `deny`: `just confine` fails on a weaker level, or on a `[workspace.lints]` entry that is not a deny-list lint as a plain string (no table, priority or group key, no other lint table).
- B7 `just confine` reads every `.rs` file outside cargo's target dirs, past strings, comments and whitespace, and fails on an attribute that silences `warnings`, `unfulfilled_lint_expectations` or a clippy group, `allow`s or `warn`s a deny-list lint, `expect`s one in a shipped crate's `src/` (`confine.toml`'s `harness` members are dev-only), starts with a macro metavariable, or names one as its lint.
- B8 `just confine` fails on a `Cargo.toml` that is neither a member nor excluded, a member build script, a second `clippy.toml`, or a member that overrides or does not inherit the workspace lints; `confine.toml`'s `unlinted` members (`wipe`) are exempt, and no other member may depend on one.
- B9 `just confine` fails on `include!`, or on a `#[path]` to anything but a `.rs` file in the tree, so no compiled code escapes the scan.
- B10 `just confine` fails on a cargo config (in the tree, its ancestors or `CARGO_HOME`), `rust-toolchain.toml` or `RUSTFLAGS` variable with an argument that starts `-A`, `-W`, `--allow`, `--warn`, `--cap-lints` or `--force-warn`, each quoted string split into arguments so a linker flag such as `link-arg=-Wl,-z,relro` passes, and on a set `CLIPPY_CONF_DIR`.
- B11 `confine.sh --self-test` (in `just confine`) plants 49 evasions in a copy of the tree, among them multi-line, string-bracketed and spaced attributes, metavariable attributes, a source dir named `target`, long-form flags, a group allow at a priority, `include!`, `#[path]` and build scripts, and requires each flagged and two linker flags passed.
- B12 Each member's direct runtime dependencies, every feature on, are the ones `deps.txt` lists: `just deps` (in `just all` and CI); `deny.toml` allows only this workspace's graph: `just deny`.
- B13 The ledger measures what is on disk: `just ledger` hands trybuild each `.rs` file of `tests/ui/fail` and `tests/ui/pass` and asserts 20 of each.
- B14 `just mutants` fails unless each package reaches its floor (base 136, testkit 109) with none missed or timed out; `just rows` counts the skipped as `cargo mutants --list --no-config` less `--list`.

## Non-claim
- N1 Copies and moves are not wiped: a `Secret<N>` moved by value, a buffer a caller copied out of `expose`, or a `Vec` handed to `SecretBytes::new` after it reallocated leaves bytes behind; the stack array a fixed-size decode fills, which is zeroed on failure but not measured; R32 covers only the storage a secret owns when dropped.
- N2 The base64url codec is `base64ct`'s; its constant-time property is that crate's claim, not checked here.
- N3 `UnixTime::from(SystemTime)` saturates instants before the epoch to 0.
- N4 `ct_eq` runs in constant time by `subtle`'s claim; no check here measures time.
- N5 An effect of two or more ops is fallible (`build` is `Overlap`, `TooLarge` or `Empty`), so an entry point that builds one returns a `Result`; a one-op effect need not (R33).
- N6 A lint attribute a macro assembles other than through a leading or lint-position metavariable (B7) is not seen by `just confine`; for the seven `forbid` lints rustc rejects it regardless (B6), so the gap is `unwrap_used`, `expect_used`, `panic`, `disallowed_methods` and `disallowed_types`.
